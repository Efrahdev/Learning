01

The complete mental movie

Before mechanisms, see the entire transformation. A frontier model is a sequence of changing states, not a single training event.

One system, six irreversible transformations
1. ExperienceHuman and machine-created text, code, images, audio, video, actions.
2. RepresentationConvert messy experience into numerical token sequences.
3. Predictive substrateTrain a Transformer to compress regularities by prediction.
4. Behaviour shapingTeach instructions, preferences, reasoning, and safe conduct.
5. Situated actionConnect the policy to tools, memory, environments, and feedback.
6. Product loopServe, monitor, discover failures, and manufacture the next curriculum.

The model begins as adjustable numbers. It ends as one component inside a governed runtime system.

Fundamental problem

How can past experience alter future behaviour?

Gradient-based learning changes parameters so future predictions and actions become more successful.

Central split

Knowledge is not behaviour

Pre-training creates broad possibilities. Post-training selects which possibilities appear when a user asks for help.

Product reality

The model is not the assistant

The assistant also includes prompts, tools, retrieval, memory, permissions, safety controls, routing, and serving infrastructure.

LOCK: The pipeline repeatedly converts experience into representation, representation into capability, capability into behaviour, and behaviour into new experience.
02

Why the order is inevitable

Each stage exists because the output of the previous stage is useful but insufficient.

The necessity chain
Raw worldRich but too messy for numerical optimisation
→
TokensComputable but contain no learned intelligence
→
Base modelKnowledgeable but follows the data distribution, not user intent
→
Assistant policyHelpful but may not search, verify, or act reliably
→
Agentic systemCapable but consequential, requiring safety and governance

If stages are skipped

  • No curation: duplicated noise gets disproportionate influence.
  • No pre-training: post-training must teach language and knowledge from tiny datasets.
  • No SFT: the model continues documents instead of reliably assisting.
  • No feedback optimisation: it imitates examples but does not systematically prefer better outcomes.
  • No production layer: excellent weights remain slow, insecure, and unusable at scale.

What order preserves

  • Broad foundation before specialisation.
  • Cheap general learning before expensive expert supervision.
  • Safe simulation before consequential action.
  • Evaluation before release.
  • Observed failure before the next training cycle.
LOCK: The sequence is forced by dependency: later stages can shape, test, or deploy capabilities only after earlier stages have created them.

The three-level lens

Use this lens at every stage so you never confuse the organisation’s pipeline with the model’s internal computation.

Bird’s-eye

Question

What state is the system in, and what must the next stage receive?

Unit

Datasets, checkpoints, policies, products.

Architecture

Question

Which modules transform information, and how are they connected?

Unit

Tokenizers, Transformers, reward models, tools.

Mechanism

Question

What local numerical operation changes the result?

Unit

Vectors, probabilities, losses, gradients, parameter updates.

One example across all three levels: pre-training
Bird’s-eye: transform a random network into a broad base model. Architecture: send token batches through repeated Transformer blocks. Mechanism: compare predicted token probabilities with the actual token, then move parameters in the direction that reduces surprise.
LOCK: Never ask only “what does this component do?” Ask what system state it transforms, which modules perform the transformation, and which numbers actually change.
04

Experience engineering

Position: beginning of the pipeline. Receives: raw human and machine artefacts. Produces: a deliberate learning curriculum.

Input → transformation → output
InputWeb, books, code, papers, images, audio, tools, licensed data
→
TransformDeduplicate, filter, score quality, remove leaks, balance sources, schedule mixtures
→
OutputTraining examples with sampling weights and metadata

Executive intuition

This is not “collect everything.” It is designing the childhood of the model. Frequency becomes influence.

Why simpler fails

Raw internet frequency measures abundance, not truth, educational value, safety, or the capability goals of the lab.

Engineering reality

Data pipelines track provenance, licensing, language, quality scores, duplication clusters, contamination, and mixture weights.

Misconception: more tokens always produce a better model
Additional tokens help only when their learning value exceeds their opportunity cost. Repeated spam can teach less than a smaller collection of diverse, high-quality demonstrations. Quality also changes the compute-optimal balance between model size and token count.
LOCK: Data curation decides which patterns get how many chances to alter the network.
05

Representation: turn experience into computable symbols

Position: between curated experience and the neural network. Produces: sequences of identifiers and vectors the Transformer can process.

“Transformers learn”Human-readable string
→
[“Trans”, “form”, “ers”, “ learn”]Reusable token pieces
→
[814, 392, 71, 5421]Discrete IDs
→
VectorsLearned coordinates carrying usable features

Why not whole words?

Vocabulary explodes and unseen words become impossible.

Why not characters?

Sequences become long, raising computation and making useful concepts harder to assemble.

Multimodal extension

Images become patches, audio becomes frames or codes, and actions become structured tokens. Different senses meet in compatible vector spaces.

Mathematical intuition
token_id → embedding lookup → vector x ∈ R^d The ID itself has no geometry. Training learns the vector so useful relationships become computationally accessible.
LOCK: Representation creates the numerical alphabet on which all later learning operates.
06

The Transformer: a programmable relationship machine

Position: the computational substrate. Receives: token vectors. Produces: context-enriched vectors and next-token probabilities.

Layered architecture
Token + position embeddings encode what is present and where.
Attention routes relevant information between positions.
Feed-forward network transforms features independently at each position.
Residual paths + normalisation preserve information and stabilise deep computation.
Repeat many times so simple relations compose into abstractions and procedures.
Output projection converts the final state into probabilities over the next token.

Physical analogy

Each token enters a conference room. Attention lets it ask: “Who here contains information relevant to my current problem?” It gathers selected messages, then locally transforms the result.

Retire the analogy

The real mechanism is weighted vector mixing. Queries and keys determine routing weights; values carry the information being routed.

Internal mechanism: attention in one compact view
Q = XWq K = XWk V = XWv scores = QKᵀ / √d weights = softmax(scores) output = weights · V

Training does not hand-code which words relate. It learns the projection matrices that make useful routing emerge.

Misconception: attention is a database lookup
Attention retrieves and combines representations inside the current context. It does not inherently guarantee factual recall, persistence, or source grounding. External retrieval exists because parameter memory and context attention have different strengths.
LOCK: A Transformer repeatedly routes information across positions and transforms it until the next useful action becomes predictable.
07

Pre-training: convert prediction errors into general capability

Position: after architecture and data. Produces: a base model containing broad latent knowledge and skills.

The learning loop, repeated at enormous scale
Context“Water freezes at”
→
PredictionProbabilities over every token
→
LossHow surprised was the model by the real token?
→
GradientWhich parameter changes reduce that surprise?
→
UpdateA tiny behavioural change

Why prediction creates intelligence

To predict diverse human artefacts, the model benefits from reconstructing the latent causes behind them: grammar, intent, concepts, code behaviour, and world regularities.

What enters

Token batches, random or partial parameters, optimiser state, training schedule, and distributed compute.

What exits

A checkpoint that can continue patterns and display broad competence, but is not yet a dependable assistant.

Mathematical intuition: loss and gradient descent
loss = −log P(correct next token | context) parameters ← parameters − learning_rate × gradient(loss)

One update is almost meaningless. Capability emerges from the accumulated direction of vast numbers of small corrections.

Practical engineering: why checkpoints and scaling laws exist
A frontier run spans large accelerator clusters and may encounter hardware faults, numerical instability, corrupt batches, or bad data mixtures. Checkpoints preserve recoverable state. Smaller experiments and scaling laws estimate how to allocate compute among parameters, tokens, and training duration before committing to the largest run.
LOCK: Pre-training is repeated error correction that compresses the statistical structure needed to predict human-created sequences.
08

Post-training: select the model you want from the model you have

Position: after broad capability. Receives: a base checkpoint plus high-quality demonstrations and judgements. Produces: an assistant policy.

Base modelCan do many things, but does not know which role to adopt.
SFTImitate excellent prompt-response demonstrations.
PreferencesLearn which acceptable response is better.
PolicyHelpful, steerable, formatted, safer assistant behaviour.

Before

“Continue text in ways similar to the pre-training distribution.”

After

“Given a user goal and policy context, choose an appropriate response style and action.”

SFT teaches examples

It moves the model toward demonstrated trajectories. It is excellent for formats, roles, tool syntax, and baseline conduct.

Preferences teach ranking

For open-ended tasks, there is no unique correct sentence. Pairwise comparisons teach relative quality, relevance, and restraint.

Why simpler fails

Pre-training learns what humans wrote, including arguments, mistakes, and toxic material. It does not identify which author or objective should govern a product assistant.

Misconception: post-training merely adds a polite personality
It also determines instruction adherence, refusal boundaries, uncertainty expression, tool-call conventions, reasoning habits, response length, and whether latent skills are reliably activated.
LOCK: Post-training does not mainly add knowledge; it teaches the model which of its many available behaviours should control the next action.
09

Reasoning and reinforcement learning: optimise trajectories, not appearances

Position: after a usable assistant exists. Receives: problems, candidate trajectories, and rewards. Produces: better search, verification, and strategy.

Imitation versus consequence

SFT: copy this route

Human solutionDesired token sequence
→
ImitationIncrease its probability

RL: reach this destination

Several attemptsExplore different routes
→
VerifierReward what works
ProblemMath, code, science, tool task
→
RolloutsMultiple reasoning/action trajectories
→
RewardTests, final answer, judge, environment
→
Policy updateSuccessful decisions become likelier
→
Harder curriculumRepeat at a higher frontier

Outcome rewards

Judge the final destination. Cheap and objective when answers, tests, or game scores are verifiable, but sparse.

Process rewards

Judge intermediate steps. Better credit assignment, but expensive and vulnerable to rewarding reasoning that merely looks good.

Test-time compute

The trained policy can spend more time sampling, checking, searching, or using tools. Training improves the searcher; inference budget enlarges the search.

The deepest intuition: RL requires a trustworthy scoreboard
Optimisation will exploit whatever the scoreboard actually measures. Therefore, the frontier advantage is often not a clever optimiser alone. It is the ability to generate hard tasks, run many attempts, verify outcomes, detect reward hacking, and convert those results into a curriculum.
Misconception: reasoning is just producing a longer chain of thought
Length is only expenditure, not quality. Useful reasoning requires allocation, decomposition, checking, error recovery, and stopping. More tokens can also amplify a wrong premise.
LOCK: Reasoning RL strengthens strategies that survive verification, while test-time compute gives those strategies room to search.
10

Tools and agents: close the loop with the external world

Position: after language and reasoning competence. Produces: a controller that can observe, act, recover, and finish.

The agent control loop
GoalWhat outcome is wanted?
→
PlanWhat is the next useful subgoal?
→
ActSearch, run code, call API, edit file
→
ObserveWhat changed? What failed?
↻
StopGoal met, blocked, or permission required

Why tools exist

Weights are finite and static. Tools provide current facts, exact computation, durable memory, and real actions.

Why agent training exists

Knowing a tool’s syntax does not teach when to call it, how to recover from failure, or how to preserve user intent across many steps.

Why long horizons are hard

Each action changes the next state. Small per-step error rates compound, and delayed outcomes make blame difficult to assign.

Dependency graph: what an agent really depends on
Agent reliability depends jointly on base-model understanding, post-trained judgement, planning, tool schemas, environment quality, permissions, context management, memory, verification, and termination rules. Adding a browser button to a model does not create an autonomous worker.
LOCK: An agent is a policy inside a feedback loop where each action alters the evidence available for the next decision.
11

Safety and evaluation: discover where capability claims fail

Position: throughout the pipeline, intensified before deployment. Produces: evidence, mitigations, and release constraints.

Data controls provenance, privacy, harmful-content handling, decontamination.
Behaviour shaping policy examples, constitutions, preference data, safer reasoning.
Capability evaluations correctness, robustness, calibration, multilingual and domain coverage.
Adversarial evaluation jailbreaks, prompt injection, exfiltration, misuse, deception.
Runtime controls tool permissions, screening, monitoring, rate limits, human approval.

Benchmark question

Can the model solve a clean, bounded task?

Deployment question

Will the entire system behave acceptably across ambiguity, attacks, distribution shift, and irreversible actions?

Misconception: safety is a refusal filter added at the end
Safety failures can originate in data, objectives, reward models, tool permissions, interfaces, or monitoring. A final classifier cannot repair every upstream failure, particularly when an agent has already taken an action.
LOCK: Evaluation is an attempt to falsify readiness, and safety is the set of upstream and runtime controls that limit the consequences of being wrong.
12

Production: turn weights into a dependable service

Position: after release criteria. Receives: checkpoints, prompts, tools, controls, and traffic. Produces: user-visible outcomes.

The assistant is a stack
Accelerators + inference engine execute the model efficiently.
Model weights provide the learned policy.
Context assembly system instructions, conversation, retrieval, memory.
Orchestration routing, tools, retries, caching, fallbacks.
Governance authentication, permissions, safety checks, monitoring.
Product experience interface, latency, citations, controls, user trust.

Quality

Choose the right model and reasoning budget, retrieve relevant context, and format answers usefully.

Economics

Batch requests, cache reusable computation, quantise where acceptable, and route easy tasks to cheaper models.

Reliability

Handle overload, failures, malicious inputs, tool errors, and degraded dependencies without losing control.

LOCK: Production quality is the behaviour of the complete stack under real constraints, not the intelligence of an isolated checkpoint.
13

The improvement flywheel

Deployment is not the end. It is the sensor that reveals the next frontier of failure.

DeployExpose the system to real task diversity
→
ObserveFailures, corrections, success signals, attacks
→
ConvertTurn cases into privacy-safe evaluations
→
TeachNew data, rewards, environments, policies
→
Re-evaluateProve the failure is fixed without regressions
↻
Critical discipline: turn a failure into an evaluation before turning it into training data. Otherwise, you may change the model without knowing whether the underlying failure was truly repaired.
LOCK: The durable advantage is a learning organisation that converts real failures into better tests, better experience, and better policies faster than competitors.
14

Reconstruct the pipeline from five necessities

If you can regenerate the system from these constraints, you understand it rather than merely remembering terminology.

Necessity 1

Experience

A blank adjustable machine needs examples of the regularities it should acquire.

Necessity 2

Computability

Experience must become numerical symbols processed by a scalable architecture.

Necessity 3

Error correction

A loss signal must tell parameters how to change so predictions improve.

Necessity 4

Goal selection

Broad prediction must be shaped into useful, preferred, and safe behaviour.

Necessity 5

Consequences

Reasoning and agency require interaction, verification, permissions, and feedback.

Necessity 6

Recursion

Real-world failures must generate the next curriculum and training cycle.

Self-test: can you answer these without terminology?
  1. Why can a prediction objective create reusable capability?
  2. Why is a knowledgeable base model not automatically an assistant?
  3. Why does imitation stop short of strategy discovery?
  4. Why is the verifier often more important than the RL algorithm?
  5. Why is an agent a feedback loop rather than a model feature?
  6. Why is the deployed assistant larger than its model weights?
ULTIMATE LOCK: A frontier assistant is a recursively improved policy: curated experience builds a predictive substrate, feedback selects and strengthens useful strategies, tools connect those strategies to consequences, and production failures become the next generation’s training signal.
